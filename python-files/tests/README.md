# تست‌های خودکار

این پوشه شامل تست‌های واحد (unit test) برای منطق خالص پروژه‌ست: تشخیص
دامنه/لینک، ذخیره و بازیابی آمار، ذخیره و بازیابی session بعد از ری‌استارت،
محدودیت حجم دانلود، و چند تابع کمکی دیگه.

## چیزی که تست **نمی‌شه**

Handlerهای اصلی تلگرام (`handle_file`, `do_send`, `handle_callback`, ...) و
هر چیزی که مستقیم نیاز به یک اتصال واقعی به تلگرام یا روبیکا داره، در این
مجموعه تست نشدن — چون:
1. نیاز به mock کردن سنگین کل شیء `Update`/`Context`/`Message` تلگرام دارن که ارزش نگهداری کمی نسبت به هزینه‌ش داره.
2. تغییرات مکرر در این توابع (که بخش اصلی توسعه‌ی آینده‌ست) باعث می‌شه این تست‌ها مدام بشکنن، نه به‌خاطر باگ واقعی بلکه به‌خاطر mock ناقص.

در عوض، منطق خالصی که این handlerها روش تکیه می‌کنن (مثل `is_allowed`,
`smart_delay`, `files_summary`, `find_sevenzip_bin`, `_get_domain`,
`is_direct_link`) به‌صورت مستقیم و بدون نیاز به mock سنگین تست شده.

## نصب و اجرا

```bash
cd python-files
pip install -r requirements.txt -r requirements-dev.txt
pytest
```

برای دیدن جزئیات بیشتر:

```bash
pytest -v
```

برای اجرای فقط یک فایل تست خاص:

```bash
pytest tests/test_downloader.py -v
```

## نکته درباره‌ی وابستگی‌های خارجی

تست‌ها بدون نیاز به `TELEGRAM_TOKEN`، `ALLOWED_USER_ID` واقعی یا اتصال به
اینترنت اجرا می‌شن. اگه کتابخانه‌های خارجی پروژه (`python-telegram-bot`،
`rubpy`، `pyrogram`، `jdatetime`، `pyzipper`) نصب نباشن، فایل
`tests/conftest.py` به‌صورت خودکار یک نسخه‌ی mock سبک جایگزینشون می‌کنه تا
import ماژول‌های پروژه شکست نخوره. اگه این کتابخانه‌ها واقعاً نصب باشن
(حالت عادی توسعه)، از همون نسخه‌ی واقعی استفاده می‌شه.

`test_downloader.py` چند تست داره که واقعاً یک پروسه‌ی زیرمجموعه (subprocess
با `python3`) اجرا می‌کنن تا رفتار واقعی async را بسنجن؛ این تست‌ها به هیچ
سروری در اینترنت وصل نمی‌شن.
